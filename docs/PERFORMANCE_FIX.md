# Критическое исправление производительности

**Дата:** 2026-01-07
**Проблема:** Синхронизация OWEN занимала 4.5 минуты вместо ~30 секунд

## Найденные проблемы

### 1. Кодировка логов (minor)

**Проблема:** Логи открываются с крокозябрами в Блокноте Windows
**Причина:** Windows Notepad не всегда корректно определяет UTF-8 даже с BOM
**Решение:** Добавлена явная вставка BOM в начало лог-файла

**Файл:** [main.py](../main.py:31-40)

```python
# Для Windows: добавляем BOM в начало файла если его нет
if sys.platform == 'win32':
    log_file = Path('logs/sync.log')
    if log_file.exists():
        with open(log_file, 'rb') as f:
            content = f.read()
        # Проверяем есть ли BOM (UTF-8 BOM = EF BB BF)
        if not content.startswith(b'\xef\xbb\xbf'):
            with open(log_file, 'wb') as f:
                f.write(b'\xef\xbb\xbf' + content)
```

**Рекомендация:** Открывайте логи в VS Code, а не в Блокноте.

### 2. КРИТИЧЕСКАЯ проблема: Цикл в update_items() (OWEN)

**Проблема:** Обновление 70,271 записей OWEN занимало **4 минуты 20 секунд**

**Данные из логов:**
```
2026-01-07 10:01:03 - Распарсено 73572 позиций
2026-01-07 10:01:04 - Начало обработки
2026-01-07 10:05:24 - Обновлено цен: 70271  ← 4 мин 20 сек!!!
```

**Причина:** В [sql_repository.py:166-185](../adapters/database/sql_repository.py:166-185) было **два цикла**, каждый выполнял UPDATE **по одной записи**:

```python
# ❌ БЫЛО (МЕДЛЕННО):
for params in data:  # 70,271 итераций!
    result = session.execute(query, params)  # Отдельный UPDATE каждый раз
    updated_count += result.rowcount

# Затем еще один цикл для legacy записей:
for params in data:  # Еще 70,271 итераций!
    result = session.execute(query_legacy, params)
    updated_count += result.rowcount
```

Это означало **140,542 отдельных SQL запроса** вместо 2-х batch запросов!

**Решение:** Заменен цикл на `executemany()` - batch операцию:

```python
# ✅ СТАЛО (БЫСТРО):
session.execute(query, data)  # Один batch UPDATE для всех 70,271 записей
updated_count += len(owen_items)

session.execute(query_legacy, data)  # Один batch UPDATE для legacy
```

**Ожидаемый результат:** Синхронизация OWEN сократится с **4.5 минут** до **30-60 секунд**

**Улучшение:** **~5x** быстрее!

---

## Техническая суть проблемы

### Почему цикл был медленным?

При выполнении SQL в цикле:
1. **Каждая итерация** отправляет запрос в БД
2. БД парсит SQL
3. БД выполняет запрос
4. БД отправляет результат
5. Python получает результат
6. **Повторить 70,271 раз**

Суммарные накладные расходы: 70,271 × (network latency + parsing + context switch) ≈ **4+ минуты**

### Почему batch быстрее?

При использовании `executemany()`:
1. Python отправляет **один запрос** с массивом данных
2. БД парсит SQL **один раз**
3. БД выполняет обновления **batch'ем** (оптимизированно)
4. Один ответ возвращается

Накладные расходы: 1 × (network + parsing) ≈ **секунды**

### Почему проблема была только у OWEN?

В коде был специальный путь для OWEN из-за legacy данных:
- Нужно обновлять записи как с `vendor='OWEN'`, так и с `vendor='ОВЕН'`
- Для этого использовались **два цикла**
- Для других вендоров уже был batch (`session.execute(query, data)`)

## Дополнительные рекомендации

### 1. Мониторинг производительности

Добавьте в конец логов время выполнения каждого этапа:

```python
# В sync_service.py
logger.info(f"⏱️ Загрузка: {download_time:.1f}s")
logger.info(f"⏱️ Парсинг: {parse_time:.1f}s")
logger.info(f"⏱️ Сравнение: {compare_time:.1f}s")
logger.info(f"⏱️ Обновление БД: {update_time:.1f}s")
```

### 2. Индексы БД

Убедитесь, что индексы созданы (в логах должно быть):
```
✅ Индексы БД проверены/созданы
```

Индексы:
- `idx_vendor_article` на `(Vendor, Part_Num)` - для быстрого поиска
- `idx_vendor` на `Vendor` - для фильтрации по вендору

### 3. PostgreSQL для production

SQLite имеет ограничения на параллельные записи. Для production рекомендуется PostgreSQL:

```python
# config/settings.py
DATABASE_URL = "postgresql://user:password@localhost/prices"
```

### 4. Async синхронизация

Для дальнейшего ускорения рассмотрите параллельную загрузку вендоров:

```python
import asyncio

async def sync_all_vendors():
    tasks = [sync_vendor_async(v) for v in vendors]
    results = await asyncio.gather(*tasks)
```

Потенциальное ускорение: **~6x** (параллельная загрузка 6 вендоров)
