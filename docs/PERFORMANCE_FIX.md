## Найденные проблемы

### 1. Кодировка логов (minor)

**Проблема:** Логи открываются с крокозябрами в Блокноте Windows
**Причина:** Windows Notepad не всегда корректно определяет UTF-8 даже с BOM
**Решение:** Добавлена явная вставка BOM в начало лог-файла

**Файл:** [main.py](../main.py:31-40)

```python
# Для Windows: добавляем BOM в начало файла если его нет
if sys.platform == 'win32':
    log_file = Path('logs/sync.log')
    if log_file.exists():
        with open(log_file, 'rb') as f:
            content = f.read()
        # Проверяем есть ли BOM (UTF-8 BOM = EF BB BF)
        if not content.startswith(b'\xef\xbb\xbf'):
            with open(log_file, 'wb') as f:
                f.write(b'\xef\xbb\xbf' + content)
```

**Рекомендация:** Открывайте логи в VS Code, а не в Блокноте.

### 2. КРИТИЧЕСКАЯ проблема: Неправильное использование batch операций

**Проблема:** Обновление большого количества записей занимало слишком долго:
- **ОВЕН**: 580.5s (9.7 мин) для 70,271 записей
- **IEK**: 270.8s (4.5 мин) для 40,789 записей

**Причина:** В [sql_repository.py](../adapters/database/sql_repository.py) использовался `session.execute(query, data)`, который в SQLAlchemy **НЕ выполняет batch операцию**, а выполняет запросы по одному!

```python
# ❌ БЫЛО (МЕДЛЕННО):
session.execute(query, data)  # Выполняет 70,271 отдельных UPDATE!
```

Каждый элемент из `data` обрабатывался как отдельный SQL запрос со всеми накладными расходами.

**Решение:** Использовать `connection.execute()` для настоящей batch операции:

```python
# ✅ СТАЛО (БЫСТРО):
connection = session.connection()
connection.execute(query, data)  # Настоящая batch операция
```

**Реальные результаты после исправления:**
- **ОВЕН**: 13.5s вместо 580.5s - **улучшение в 43 раза**!
- **IEK**: 15.5s вместо 270.8s - **улучшение в 17.5 раз**!
- **CHINT**: 3.6s - работает отлично

**Файлы изменены:**
- `adapters/database/sql_repository.py:85-115` - add_items()
- `adapters/database/sql_repository.py:115-166` - update_items()

## Техническая суть проблемы

### Почему session.execute(query, data) был медленным?

В SQLAlchemy 2.0, `session.execute(query, data)` с массивом параметров **НЕ выполняет batch операцию**:

1. **Каждый элемент** из data обрабатывается отдельно
2. БД парсит SQL для каждого запроса
3. БД выполняет каждый UPDATE отдельно
4. **Повторить 70,271 раз для ОВЕН**

Суммарные накладные расходы: 70,271 × (parsing + execution + I/O) ≈ **9.7 минут**

### Почему connection.execute() быстрее?

При использовании `connection.execute(query, data)`:
1. Python отправляет **batch запрос** с массивом данных
2. SQLAlchemy использует **executemany mode**
3. БД парсит SQL **один раз**
4. БД выполняет обновления **batch'ем** (оптимизированно)

Накладные расходы: 1 × (parsing + batch execution) ≈ **13 секунд**

### Почему проблема проявлялась не у всех вендоров?

Проблема была у всех вендоров, но заметна только при большом количестве обновлений:
- **ОВЕН**: 70,271 обновлений - очень медленно (9.7 мин)
- **IEK**: 40,789 обновлений - медленно (4.5 мин)
- **DKC**: 6 обновлений - незаметно
- **KEAZ**: 0 обновлений - нет проблемы

## Дополнительные рекомендации

### 1. Мониторинг производительности

Добавьте в конец логов время выполнения каждого этапа:

```python
# В sync_service.py
logger.info(f"⏱️ Загрузка: {download_time:.1f}s")
logger.info(f"⏱️ Парсинг: {parse_time:.1f}s")
logger.info(f"⏱️ Сравнение: {compare_time:.1f}s")
logger.info(f"⏱️ Обновление БД: {update_time:.1f}s")
```

### 2. Индексы БД

Убедитесь, что индексы созданы (в логах должно быть):
```
✅ Индексы БД проверены/созданы
```

Индексы:
- `idx_vendor_article` на `(Vendor, Part_Num)` - для быстрого поиска
- `idx_vendor` на `Vendor` - для фильтрации по вендору

### 3. PostgreSQL для production

SQLite имеет ограничения на параллельные записи. Для production рекомендуется PostgreSQL:

```python
# config/settings.py
DATABASE_URL = "postgresql://user:password@localhost/prices"
```

### 4. Async синхронизация

Для дальнейшего ускорения рассмотрите параллельную загрузку вендоров:

```python
import asyncio

async def sync_all_vendors():
    tasks = [sync_vendor_async(v) for v in vendors]
    results = await asyncio.gather(*tasks)
```

Потенциальное ускорение: **~6x** (параллельная загрузка 6 вендоров)
