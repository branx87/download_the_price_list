# ERP отчёт: 1474 добавлено но в отчёте 1000 + "This Connection is closed"

**Date:** 2026-02-19 13:30
**Files:** domain/services/erp_sync_service.py, adapters/database/sql_repository.py
**Severity:** high

## Problem

1. Бот сообщает "Добавлено новых: 1474", но Excel-отчёт содержит ровно 1000 строк в секции "добавлено".
2. Критическая ошибка: "This Connection is closed" в конце синхронизации.

## Root Cause

**Проблема 1: Искусственный лимит added_details**

В `erp_sync_service.py`:
```python
result.added += 1
if len(result.added_details) < 1000:  # ← лимит 1000
    result.added_details.append({...})
```

Счётчик `result.added` инкрементируется для ВСЕХ вставленных записей (1474),
но `added_details` (используется в Excel-отчёте) ограничен 1000 элементами.
Лимит был введён в патче 2026-02-19-01.00 "для экономии RAM при 31554 новых записей",
но теперь с правильной нормализацией добавляется гораздо меньше (~1474), и лимит только
вносит путаницу (счётчик ≠ строкам в отчёте).

**Проблема 2: Повторное использование закрытого connection**

В `bulk_set_article_pc`, `add_erp_items` (UPDATE и INSERT части):
```python
with self.SessionLocal() as session:
    connection = session.connection()  # ← получаем ОДИН РАЗ до цикла
    for batch in batches:
        connection.execute(query, batch)
        session.commit()  # ← после commit() SQLAlchemy возвращает connection в пул
        # Следующая итерация: connection уже закрыт! → "This Connection is closed"
```

SQLAlchemy после `session.commit()` возвращает underlying connection в connection pool.
Переменная `connection` указывает на уже невалидный объект. При 1474 записях (2 батча по 1000)
это проявляется на второй итерации.

## Solution

**1. Убран лимит 1000 в `erp_sync_service.py`:**
```python
result.added += 1
result.added_details.append({...})  # без ограничений
```

**2. `connection = session.connection()` перенесён внутрь цикла** во всех трёх местах:
- `bulk_set_article_pc()`
- `add_erp_items()` — UPDATE часть
- `add_erp_items()` — INSERT часть

```python
for batch_idx in range(...):
    # Получаем connection на каждую итерацию — после commit() он возвращается в пул
    connection = session.connection()
    connection.execute(query, batch)
    session.commit()
```

## Prevention

**Правило для SQLAlchemy batch операций с промежуточными commit:**
- `session.connection()` НЕЛЬЗЯ вызывать один раз до цикла если внутри цикла есть `session.commit()`
- После каждого `commit()` нужно заново получать `connection = session.connection()`
- Альтернатива: `session.execute()` вместо `connection.execute()` — session сама управляет connection

**Правило для added_details:**
- Лимит в added_details оправдан только если ожидаются десятки тысяч новых записей
- При нормальной работе (нормализация настроена) количество новых записей мало → лимит не нужен
