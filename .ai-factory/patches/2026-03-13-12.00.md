# ArticlePC хранился в uppercase — несовпадение с кодами в 1C-ERP

**Date:** 2026-03-13 12:00
**Files:** domain/services/erp_sync_service.py, adapters/database/sql_repository.py
**Severity:** medium

## Problem

При синхронизации `/erp` ArticlePC (код из 1C) записывался в БД в верхнем регистре
(`.upper()`) и с удалёнными пробелами, хотя в самой 1C-ERP код хранится как есть.
Например: 1C отдаёт `"Пс-0001001"`, а в БД оседало `"ПС-0001001"`.
Это вело к несоответствию между кодами в 1C и SQL-базе.

## Root Cause

В `erp_sync_service.py` переменная `code` использовалась для ДВУХ разных целей:
1. Поиск/сравнение (нужен uppercase)
2. Запись в БД (нужен raw)

Строка `code = code_raw.upper()` превращала код в uppercase, и этот же объект
подставлялся в `to_insert`, `to_update_article_pc`, `to_update_raw_values`.
Намерение "нормализуем для сравнения" перемешалось с фактическим хранением.

## Solution

**erp_sync_service.py:**
- Переименована переменная: `code` → `code_upper` (только для поиска)
- Везде где происходит запись в БД — используется `code_raw` (оригинальное значение из 1C)
- `get_all_vendor_part_num_pairs()` теперь возвращает 4-tuple с `article_pc_raw`
  (реально хранимое значение в БД), чтобы использовать его как WHERE-ключ при UPDATE
- При каждой синхронизации: если `stored_article_pc != code_raw` — добавляем
  `new_article_pc` в элемент `to_update_raw_values` для исправления регистра
  существующих записей без создания дублей

**sql_repository.py:**
- `get_all_vendor_part_num_pairs()`: добавлен 4-й элемент кортежа `article_pc_raw`
  (`.strip()` без `.upper()`)
- `bulk_update_raw_values()`: поддержка ключа `new_article_pc` — если задан,
  добавляется `SET ArticlePC = new_article_pc` в UPDATE (как в MSSQL через temp table,
  так и в SQLite через прямой UPDATE). WHERE-ключ остаётся `article_pc` (старое значение).

## Prevention

- Разделять "нормализация для поиска" и "значение для хранения" — разные переменные
- При загрузке данных из внешних систем: нормализованные переменные называть `*_norm`
  или `*_upper`, хранимые — `*_raw` или без суффикса
- Code review: проверять, что значение, которое пишется в БД, пришло из raw-источника,
  а не из нормализованной переменной
