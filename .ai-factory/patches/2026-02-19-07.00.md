# ERP sync: дубликаты из-за несогласованной нормализации данных

**Date:** 2026-02-19 07:00
**Files:** adapters/database/sql_repository.py, domain/services/erp_sync_service.py
**Severity:** critical

## Problem

ERP-синхронизация создавала **массивные дубли**:
- Ожидалось: ~1500 новых позиций
- Фактически: **16809 новых позиций** (вместо UPDATE ArticlePC делался INSERT дублей)
- Также ошибка: **"This Connection is closed"** при batch-операциях

Пользователь повторно загружал прайс через Excel, но ситуация не менялась — каждый запуск `/erp` создавал тысячи дублей.

## Root Cause

**Проблема 1: Несогласованная нормализация Vendor+Part_Num**

`get_all_vendor_part_num_pairs()` возвращал **сырые данные из БД** (только `.strip()`):
```python
# БД → existing_pairs
return {(row[0].strip(), row[1].strip()) for row in result}
# Пример: ('ИЭК', 'ABC-123')
```

`erp_sync_service.py` сравнивал с **полностью нормализованными данными**:
```python
manufacturer = DataNormalizer.normalize_vendor_name(manufacturer_raw)  # .strip().upper()
article = DataNormalizer.normalize_article(article_raw)  # .strip() + убрать пробелы + .upper()

if (manufacturer, article) in existing_pairs:  # ('ИЭК', 'ABC123')
    # UPDATE ArticlePC
```

**Пример как создавались дубли:**
```
БД: Vendor='иэк', Part_Num='abc-123'
existing_pairs после .strip() = {('иэк', 'abc-123')}

1C: manufacturer='IEK', article='abc 123'
После нормализации: ('ИЭК', 'ABC123')  ← uppercase + без дефиса/пробелов

Проверка: ('ИЭК', 'ABC123') in {('иэк', 'abc-123')} → False ❌
Результат: INSERT дубль вместо UPDATE ArticlePC
```

**Проблема 2: Несогласованная нормализация ArticlePC (code)**

`get_all_article_pcs()` возвращал:
```python
return {row[0].strip().upper() for row in result if row[0]}
# Пример: {'KEA12345'}
```

`erp_sync_service.py` сравнивал с:
```python
code = (item.get('code') or '').strip()  # БЕЗ .upper()!
if code in existing_article_pcs:
```

Пример:
```
БД: ArticlePC='kea12345' → после .upper() = 'KEA12345'
1C: code='Kea12345' → БЕЗ .upper() = 'Kea12345'

Проверка: 'Kea12345' in {'KEA12345'} → False ❌
Результат: INSERT дубль вместо пропуска
```

**Проблема 3: "This Connection is closed"**

При ошибке внутри batch-операции сессия закрывалась, но цикл продолжался:
```python
with self.SessionLocal() as session:
    connection = session.connection()
    for batch in batches:
        connection.execute(query, batch)  # Если ошибка - сессия закрыта
        session.commit()                  # Следующая итерация - "Connection is closed"
```

## Solution

**1. Применена полная нормализация в `get_all_vendor_part_num_pairs()`:**
```python
def get_all_vendor_part_num_pairs(self) -> set:
    # ...
    return {
        (
            DataNormalizer.normalize_vendor_name(row[0]) if row[0] else '',
            DataNormalizer.normalize_article(row[1]) if row[1] else ''
        )
        for row in result
    }
```
Теперь:
- БД: ('иэк', 'abc-123') → после нормализации: **('ИЭК', 'ABC123')**
- 1C: ('IEK', 'abc 123') → после нормализации: **('ИЭК', 'ABC123')**
- Сравнение: ('ИЭК', 'ABC123') in {('ИЭК', 'ABC123')} → **True** ✅

**2. Применена полная нормализация в `get_all_article_pcs()`:**
```python
def get_all_article_pcs(self) -> set:
    # ...
    return {row[0].strip().upper() for row in result if row[0]}
```
Уже было правильно, но для консистентности улучшена документация.

**3. Применена нормализация code в `erp_sync_service.py`:**
```python
code_raw = (item.get('code') or '').strip()
code = code_raw.upper()  # Нормализуем для сравнения с БД

if code in existing_article_pcs:  # Теперь сравниваем оба в uppercase
```

**4. Добавлена обработка ошибок в batch-операциях:**
```python
with self.SessionLocal() as session:
    try:
        connection = session.connection()
        for batch in batches:
            connection.execute(query, batch)
            session.commit()
    except Exception as e:
        logger.error(f"Ошибка на батче {batch_num}: {e}", exc_info=True)
        session.rollback()
        raise  # Прерываем цикл, не продолжаем с закрытой сессией
```

Применено к:
- `bulk_set_article_pc()`
- `add_erp_items()` — UPDATE часть
- `add_erp_items()` — INSERT часть

## Prevention

**Золотое правило нормализации данных:**

> Если данные из БД и данные из внешнего источника сравниваются — они ДОЛЖНЫ проходить через ОДИНАКОВУЮ нормализацию.

**Чеклист:**
1. Определить все места где загружаются данные из БД для сравнения (`get_all_*`)
2. Определить все места где данные из внешнего источника нормализуются
3. Убедиться что применяется **ТА ЖЕ** нормализация:
   - Vendor: `DataNormalizer.normalize_vendor_name()` → `.strip().upper()`
   - Article/Part_Num: `DataNormalizer.normalize_article()` → `.strip()` + убрать пробелы + `.upper()`
   - ArticlePC/code: `.strip().upper()`

**Паттерн для batch-операций с одной сессией:**
```python
with self.SessionLocal() as session:
    try:
        connection = session.connection()
        for batch in batches:
            # операции
            session.commit()
    except Exception as e:
        logger.error(f"Ошибка: {e}", exc_info=True)
        session.rollback()
        raise  # ВАЖНО: не продолжаем с закрытой сессией
```

**Тестирование нормализации:**
При добавлении новых методов загрузки из БД или внешних источников:
1. Проверить примеры с разным регистром: 'abc', 'ABC', 'Abc'
2. Проверить примеры с пробелами: 'abc 123', 'abc-123', 'abc123'
3. Убедиться что сравнение находит совпадения в обоих направлениях
