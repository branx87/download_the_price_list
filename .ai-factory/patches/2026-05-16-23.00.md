# update_items возвращал 0 для позиций с Status IS NULL

**Date:** 2026-05-16 23:00
**Files:** adapters/database/sql_repository.py
**Severity:** high

## Problem

`sync_KEAZ` (и потенциально другие вендоры) сообщал «Изменений цены: 21553», но
фактически записывал в БД **0** строк (`updated=0`). После sync проверка `check_KEAZ`
показывала те же 21553 изменения — как будто sync не выполнялся.

## Root Cause

В MSSQL выражение `NULL != 'discontinued'` вычисляется в `NULL` (UNKNOWN),
а не в `TRUE`. WHERE-условие в `update_items`:

```sql
WHERE tp.Status != 'discontinued'
```

пропускало **все** строки с `Status = NULL`. Если позиции были залиты в БД вручную
без явного значения Status — они навсегда "зависали" без обновления.

`get_items_by_vendor` корректно обрабатывает NULL: `(Status IS NULL OR Status != 'disappeared')`,
поэтому позиции находились при проверке, но не обновлялись при синхронизации.

## Solution

MSSQL-путь:
```sql
-- было
WHERE tp.Status != 'discontinued'
-- стало
WHERE (tp.Status IS NULL OR tp.Status != 'discontinued')
```

SQLite-путь (симметрично):
```sql
-- было
WHERE Vendor = :vendor AND Part_Num = :article AND Status != 'discontinued'
-- стало
WHERE Vendor = :vendor AND Part_Num = :article AND (Status IS NULL OR Status != 'discontinued')
```

## Prevention

- В SQL сравнение с NULL через `!=` / `=` всегда возвращает NULL — проверять через `IS NULL`
- Добавить `NOT NULL DEFAULT 'active'` на колонку Status при создании таблицы
- Проверять `updated` vs `price_changes_count` в результате sync: если `updated=0`
  при `price_changes > 0` — это красный флаг
