# CHINT: URL изменился на датированный формат

**Date:** 2026-04-14 10:30
**Files:** adapters/downloaders/chint_downloader.py
**Severity:** high

## Problem

Бот сообщал `✅ CHINT: 8798` без изменений, хотя новый прайс CHINT содержал
обновлённые цены (пример: артикул 271383 — в БД 66631.48, в реальном файле 89652.65)
и значительно больше позиций (10685 vs 8798).

## Root Cause

CHINT изменил формат URL для публикации прайса. Старый датированный URL:
```
https://chint.ru/upload/price-list/date/Price-list-CHINT.xlsx  → 403
```
Новый формат включает дату в имени файла:
```
https://chint.ru/upload/price-list/date/Price-list-CHINT_DD-MM-YYYY.xlsx → 200 OK
```
Статичный URL (`/upload/price-list/Price-list-CHINT.xlsx`) продолжает возвращать 200,
но отдаёт устаревший файл (8797 позиций, старые цены). Именно его скачивал бот —
сравнение с БД давало нулевые изменения, отчёт выглядел успешным.

## Solution

`ChintDownloader` переписан:
- Метод `_build_candidate_urls()` генерирует список URL: сначала датированные
  (от сегодня назад 14 дней), затем статичные как fallback.
- При первом совпадении (status=200, размер > 100 KB) файл сохраняется и возвращается.
- Логирование с префиксом `[FIX]` показывает какой именно URL сработал.

Новый файл (10685 позиций) совместим с существующим `ExcelParser`:
- Лист `Price-list` по-прежнему первый (sheet_name=0).
- Заголовки на той же строке 11 (индекс 10).
- Колонка `Тариф с НДС, руб` на месте (ExcelParser ищет по имени, не по индексу).
- Новая колонка `Тариф без НДС, руб` игнорируется парсером.

## Prevention

- При смене URL у вендора проверять все три группы URL: датированные, статичные, API.
- Если после очередного sync вендор показывает 0 изменений при сохранении ✅ —
  проверить вручную: скачать файл с URL и сравнить число позиций с БД.
- Для CHINT хранить шаблон `_DATE_URL_TEMPLATE` и число дней lookback в классе —
  при следующем изменении URL менять только эти константы.
