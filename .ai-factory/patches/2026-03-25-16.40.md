# float в row_values при парсинге Excel + отсутствие retry в IEK

**Date:** 2026-03-25 16:40
**Files:** adapters/parsers/excel_parser.py, adapters/downloaders/iek_downloader.py
**Severity:** high

## Problem

`/sync_all` — все 6 вендоров падали с ошибками:

- KEAZ, ОВЕН, EKF, CHINT, DKC: `TypeError: argument of type 'float' is not iterable`
  в `excel_parser.py` при поиске строки заголовков.
- IEK: `NameResolutionError` — DNS-ошибка без retry, первая попытка сразу фейлилась.

## Root Cause

**Excel parser:** В pandas 2.0+ `.str.lower()` на Series с object dtype возвращает `np.nan` (float)
для ячеек с NaN-значениями, даже если перед этим был вызван `.astype(str)`.
Новые прайс-листы (март 2026) содержат пустые ячейки в первых строках, которых не было
в январских файлах — отсюда появился float в `row_values`.

Два места:
1. `_find_header_row` (строка ~169): `df.iloc[idx].astype(str).str.lower().tolist()`
2. DKC-секция (строка ~95): аналогично

**IEK:** `download()` переопределяет базовый метод и не использует retry-логику
`BaseDownloader`. Первая попытка DNS-запроса к `www.iek.ru` падала без повтора.

## Solution

**excel_parser.py:** Заменил `.astype(str).str.lower().tolist()` на list comprehension,
которая не использует pandas `.str` accessor:
```python
row_values = [str(v).lower() for v in df.iloc[idx].tolist()]
```
`str(float('nan'))` → `'nan'`, который безопасно проверяется через `in`.

**iek_downloader.py:** Вынес POST-запрос в отдельный метод `_post_with_retry()`
с той же логикой retry что в `BaseDownloader` (3 попытки, задержки 5/15/30с).

## Prevention

- При использовании pandas `.str` accessor всегда проверять, что данные не содержат NaN.
  Предпочтительно: list comprehension через `str()` вместо pandas .str accessor.
- При переопределении `download()` в downloaders — обязательно добавлять retry для
  сетевых ошибок, или переиспользовать логику из базового класса.
