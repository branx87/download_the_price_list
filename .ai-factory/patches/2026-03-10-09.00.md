# Нормальное логирование бота в файл + подавление HTTP-логов

**Date:** 2026-03-10 09:00
**Files:** run_bot.py, bot/handlers.py
**Severity:** low

## Problem

Бот логировал мусор в консоль:
- `HTTP Request: POST https://api.telegram.org/...` — сотни строк от httpx на каждый getUpdates/sendMessage
- `DKC stdout length: 4600`, `DKC returncode: 0`, `DKC STDERR CONTENT:` — отладочные заглушки, оставшиеся в коде
- Логи бота не писались в файл `logs/sync.log`, только в stdout

## Root Cause

1. `run_bot.py` настраивал `basicConfig` только с `StreamHandler` и без `FileHandler` — файл `logs/sync.log` не использовался ботом (только `main.py` как subprocess писал туда).
2. Логгеры `httpx`, `httpcore`, `telegram` не фильтровались — все INFO запросы к Telegram API попадали в вывод.
3. В `bot/handlers.py` в обработчике кнопки `sync_` остался DKC-специфичный отладочный блок (`if vendor == 'DKC': logger.info(...)`) с закомментированным аналогом в `sync_all_command`.

## Solution

- `run_bot.py`: добавлены `FileHandler` на `logs/sync.log` (UTF-8) и `StreamHandler`; формат изменён на `%(name)s` для видимости источника; подавлены INFO-логи `httpx`, `httpcore`, `telegram`.
- `bot/handlers.py`: удалён DKC-debug блок, вместо него — единый `logger.info(f"[SYNC] {vendor}: total=...")` после успешного парсинга результата. Аналогично в `sync_all_command`.
- `bot/handlers.py` `_run_erp_sync`: добавлен `logger.info(f"[ERP] Синхронизация завершена: ...")` после получения результата.

## Prevention

- Не оставлять вендор-специфичные (`if vendor == 'DKC'`) отладочные блоки в продовом коде.
- Настраивать логирование бота в `run_bot.py` симметрично `main.py` — оба должны писать в один файл.
- После добавления нового обработчика команды — сразу добавлять `logger.info` с результатом.
