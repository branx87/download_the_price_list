# /duplicates: поиск дублей по ArticlePC + отчёт удалённых + ERP обновляет Descr

**Date:** 2026-02-26 10:00
**Files:** adapters/database/sql_repository.py, domain/services/erp_sync_service.py, bot/handlers.py
**Severity:** medium

## Problem

1. `/duplicates` находил дубли только по `Vendor+Part_Num`. Не учитывались записи с одинаковым `ArticlePC` (один код 1С у нескольких строк с разными производителями/артикулами).

2. При удалении дублей не было отчёта — пользователь видел только "Удалено N строк" без деталей.

3. При `/erp` синхронизации, если запись найдена по `ArticlePC` и изменился `Vendor`/`Part_Num` в 1С — обновлялись только эти поля, но не `Descr` (название).

## Root Cause

**Проблема 1:** `get_duplicates_info/sample/delete_duplicates` работали только с GROUP BY `Vendor, Part_Num`. Группировка по `ArticlePC` отсутствовала.

**Проблема 2:** `delete_duplicates()` возвращал только `int`. Строки, которые будут удалены, нигде не сохранялись.

**Проблема 3:** В `erp_sync_service.py` step 1 (found by ArticlePC) добавлял в `to_update_raw_values` только `{vendor, part_num, article_pc}`, не включая `descr`. `bulk_update_raw_values()` не умел обновлять `Descr`.

## Solution

**sql_repository.py:**
- `delete_duplicates()` → возвращает `(deleted_count, deleted_items)`. Перед DELETE делает SELECT TOP 50 строк которые будут удалены, для отчёта.
- Добавлены: `get_duplicates_info_by_article_pc()`, `get_duplicates_sample_by_article_pc()`, `delete_duplicates_by_article_pc()` — аналоги для дублей по ArticlePC. Стратегия: сохранять строку с заполненным `Vendor`, затем самую свежую.
- `bulk_update_raw_values()` — добавлена поддержка опционального поля `descr`. Если хотя бы один элемент содержит `descr` — обновляет `Descr` в БД (и MSSQL через tmp table, и SQLite через executemany). SET-clause строится динамически.

**erp_sync_service.py:**
- В step 1 (found by ArticlePC) добавлено `'descr': name` в `to_update_raw_values`.

**handlers.py:**
- `duplicates_command`: показывает оба типа дублей — по `Vendor+Part_Num` и по `ArticlePC`. Кнопки разбиты на две строки.
- Добавлены callbacks: `dup_apc_preview`, `dup_apc_delete`.
- `dup_delete` и `dup_apc_delete` теперь распаковывают `(deleted, deleted_items)` и формируют отчёт удалённых строк (до 50).

## Prevention

- При добавлении новых ключей дублирования — делать полный набор методов (info/sample/delete) сразу.
- `delete_*` методы в репозитории должны возвращать кортеж `(count, items)` для возможности отчёта.
- `bulk_update_*` методы должны поддерживать опциональные поля через `has_field = any(...)` паттерн.
