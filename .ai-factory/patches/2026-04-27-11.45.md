# Рефактор ExcelParser: конфиг вместо if/elif по вендору + добавлен МЕКО

**Date:** 2026-04-27 11:45
**Files:** adapters/parsers/excel_parser.py, vendors/registry.py, bot/handlers.py
**Severity:** low

## Problem

ExcelParser содержал `if vendor == 'IEK'` и `elif vendor == 'DKC'` — каждый новый вендор с нестандартным форматом добавлял ещё один блок. Это затрудняло добавление новых прайсов.

## Root Cause

Специфика парсинга (номер строки заголовков, объединение двух строк) была захардкожена в методе `parse()` вместо того чтобы передаваться через конфиг.

## Solution

Добавлены три параметра `parser_config`:
- `sheet_name_pattern` — находит лист по подстроке в имени
- `header_row` — явный 0-based индекс строки заголовков
- `header_rows_combine` + `data_start_row` — объединение двух строк в заголовок (IEK)

Логика `parse()` теперь читает стратегию из конфига через `_resolve_sheet()` и `_load_dataframe()`. Дублирование колонок обрабатывается автоматически во всех случаях.

IEK в VendorRegistry получил `header_rows_combine: [5, 6], data_start_row: 7`. Добавлен МЕКО: `sheet_name_pattern: 'Прайс', header_row: 0`.

В `_FILENAME_VENDOR_MAP` бота добавлена запись `'меко': 'МЕКО'`.

## Prevention

- Перед добавлением нового вендора — только `VendorConfig` в registry.py, новый код не нужен если формат стандартный
- Нестандартный формат (2 строки заголовков, нестандартный лист) решается через конфиг без изменения ExcelParser
