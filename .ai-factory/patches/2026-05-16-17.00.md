# Синхронизация перезаписывала discontinued, PriceText не менялся

**Date:** 2026-05-16 17:00
**Files:** adapters/database/sql_repository.py
**Severity:** high

## Problem

1. Позиции, помеченные `пометить VENDOR АРТИКУЛ`, теряли статус `discontinued` после следующей синхронизации. Пользователь помечал 13.05, а на следующий день `снятых нет`.
2. После пометки поле `PriceText` оставалось прежним — в прайс-листе отображалась старая цена, а не "Снят с производства".

## Root Cause

`update_items` при синхронизации выполнял `SET Status = 'price_changed'` без условия `WHERE Status != 'discontinued'`. Цепочка: `discontinued` → (sync `update_items`) → `price_changed` → (`reset_changed_status`) → `active`. Статус терялся за два шага.

`mark_as_discontinued` обновлял только `Status` и `Storage` (замена), не трогая `PriceText`.

## Solution

- `update_items` (MSSQL): добавлен `WHERE tp.Status != 'discontinued'` в JOIN UPDATE
- `update_items` (SQLite): добавлен `AND Status != 'discontinued'` в WHERE
- `mark_as_discontinued`: добавлен `PriceText = 'Снят с производства'` в оба UPDATE (с заменой и без)
- `unmark_discontinued`: добавлен `PriceText = ''` в SET при восстановлении

## Prevention

При любом массовом UPDATE по Vendor/Part_Num проверять: не перетираем ли вручную выставленные статусы (`discontinued`). Правило: синхронизация не должна трогать записи со статусами, проставленными администратором вручную.

Существующие помеченные позиции (без PriceText) нужно перепометить после деплоя.
